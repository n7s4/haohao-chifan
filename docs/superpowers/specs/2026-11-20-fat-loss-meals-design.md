# 减脂餐模块 设计

日期：2026-11-20　状态：待确认

## 为什么做
发现页现在只有 6 道内置菜，「轻食」只是一个按热量（<420 千卡）的筛选按钮。想给**来找菜的人**一个专门的减脂餐入口：点进去就有一批现成、靠谱、家里能做的减脂菜。重点在菜谱内容和发现页，不做每日热量目标、打卡、体重记录（那是另一类需求，用户已明确不选）。

## 目标 / 非目标
- 目标：发现页有醒目的「减脂餐」入口；专题页里有 12–15 道内置减脂菜，可按早餐 / 正餐 / 加餐切换；这些菜在详情页显示蛋白质、碳水、脂肪。
- 非目标：每日热量目标、计划页超标提醒、社区「减脂」标签、用户自建菜填营养数据。
- 反目标：内容空洞或不像减脂餐（高油高糖却挂减脂名头）；为此要求用户重新装包。

## 做法（已选）
考虑过三种：①发现页专题卡片 + 专题页（选中）；②把「轻食」筛选改名为「减脂餐」——改动小但不像模块、没地方放说明和分餐；③底部新增标签页——底栏已有 5 个，太重。用户选 ①。

## 设计
**内容**（我的判断，可改）：中式家常为主，加 2–3 道简单西式轻食。早餐约 4 道、正餐约 8 道、加餐约 3 道。每道：
- 正餐 ≤ 500 千卡、早餐 ≤ 400、加餐 ≤ 200；蛋白质尽量高（正餐 ≥ 25g）。
- 少油做法（蒸、煮、凉拌、少油快炒），食材家常好买，步骤和现有内置菜一样详细（含火候、小贴士、分步时长）。
- 营养数据是按常见食材成分估算的，专题页说明里写明「数值为估算」。

**数据**：在 `Recipe` 上加两个可选字段，只有这批内置菜填：
- `nutrition?: { protein: number; carbs: number; fat: number }`（克）
- `fatLoss?: "breakfast" | "main" | "snack"`（属于减脂餐专题及其分餐）
插画复用现有 5 种（salad / rice / soup / toast / pasta），不新画。

**界面**：
- 发现页：在「菜谱 / 社区」切换上方放一张「减脂餐」卡片（两种模式都看得到，因为默认是社区模式）：标题、「N 道 · 每道 500 千卡以内」、箭头。
- 新页面 `/fat-loss`：顶部简短说明（怎么用、数值为估算）；分段切换「全部 / 早餐 / 正餐 / 加餐」；列表每项显示插画、菜名、热量、蛋白质，点进现有菜谱详情页。
- 菜谱详情页：有 `nutrition` 时，在现有热量那一栏旁边加蛋白质 / 碳水 / 脂肪三项。
- 这批菜也出现在发现页「菜谱」的普通列表里，可收藏、加入计划，和其他内置菜一样。

**发布**：只改 JS 和数据，通过 OTA（preview 渠道）推送，不用重新装包；不动数据库。

## 留给实现者
卡片和专题页的具体视觉沿用现有发现页风格（颜色、圆角、阴影来自 theme）；菜谱具体菜名和步骤由实现时写定，满足上面的热量 / 蛋白质约束。
